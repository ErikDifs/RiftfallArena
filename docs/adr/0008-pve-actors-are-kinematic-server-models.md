# PvE actors are kinematic server models

A moving PvE actor (the first is the [Rift Warden](../rift-warden-design.md), the second the [regular monster](../regular-monster-design.md), which reuses the extracted movement and Territory primitives) is an anchored model that server code moves directly each frame. It has no Humanoid locomotion, no physics impulses, no `PathfindingService` and no client network ownership. Its body does not collide with characters, and its combat target is the separate fixed Hitbox, as in [ADR-0004](0004-fixed-gameplay-hitbox-independent-of-appearance.md). It still registers as a combat target with a hidden Humanoid for Health, as Sentries do, so damage, Shield, Statuses and Reactions use the shared model.

A future reader may expect a Humanoid NPC driven by `MoveTo`, and `monsters.md` describes direct movement with pathfinding when stuck. A physics-driven NPC was rejected because players could push it, forced movement (Tidal Knockback, a Hook pull) would move it, it could fall, and it would need network-ownership handling. All of those contradict rules the Arena depends on. Kinematic movement makes them true by construction and keeps the actor on the server's authority. The cost is that the actor ignores terrain on its own, so each actor's stage must be authored open and validated, and obstacle handling is a level-design rule, not a navigation system.

If an actor genuinely needs routed navigation, extend this decision for that actor deliberately. Do not add pathfinding to the Warden to avoid fixing its stage.
