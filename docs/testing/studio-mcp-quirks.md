# Studio MCP testing quirks

What the `Roblox_Studio` MCP can and can't verify in Riftfall Arena playtests, and the traps that have given false results. Found from Ticket 1 onwards. Read this before any Studio test run. It is the project's canonical testing reference, so add new quirks here.

Code is edited through the MCP rather than Rojo, as [ADR-0005](../adr/0005-game-code-lives-in-studio-edited-through-mcp.md) sets out.

- `multi_edit` reads a dot in a script path as a separator, so `Foo.spec` makes a folder. Avoid dots in instance names.
- `user_mouse_input` moves don't produce look input while the mouse is locked, so only the user can test mouse-look. Button down and up do work, but every call needs an x/y or `moveTo`, or a mouseButtonUp fails and leaves the button held.
- `screen_capture` does not show `AlwaysOnTop` BillboardGuis. It's unknown whether they render normally, so Hud elements are used where they must be verified.
- `AbsolutePosition` inside a BillboardGui is relative to the billboard, so it says nothing about where it is on screen.
- After teleporting a character from the client, wait over 1 s before a server-side check: the server sees the new position late, and a 0.3 s wait produced a false range failure.
- Scripts can't be edited during Play. Stop Play first.
- The studio id changes when Studio reopens, so call `list_roblox_studios` again.
- `game.PlaceVersion` may not refresh after a publish, so it doesn't prove a publish hasn't happened.
- `require` inside `execute_luau` gives a fresh module instance, not the running game's. It can't reach live state such as `Movement`, though it's useful for testing a module with fakes. Instances, attributes and tags are shared. To change config for a live test, edit it in Edit mode and revert it after.
- Since Ticket 4, Movement Validation corrects test teleports. Move the character in hops of about 8 studs every 0.5 s. `character_navigation` reported success once without moving it.
- The user can be in the same Studio session during tests. Unexplained Casts or a stopped Play may be them, so ask before calling it a bug.
- `settings().Network` persists across Studio restarts: record the starting values and restore them after a latency test.
- A built-in `rbxasset://` sound can fail to load (`swoosh.wav` does). Check `IsLoaded` before relying on one.
- To reach live server modules, add a temporary Script under `Server` that requires them and exposes a BindableFunction in ServerStorage, then call it from `execute_luau`. Name it TEMPORARY, delete it after and grep for the word. It can fire real projectiles at the player, since no dummy shoots.
- `screen_capture` works during Play and shows the player's real view, Hud included, but ignores its camera arguments, so stand where you need the view.
- The viewport can stop rendering mid-session (seen 2026-11-07, Ticket 6), and restarting Play doesn't fix it. Then `RenderStepped` never fires (Heartbeat still does), tweens freeze, `user_keyboard_input` reports success without reaching `UserInputService`, and `user_mouse_input` and `screen_capture` hang past 120 s. Check by counting `RenderStepped` for a second before trusting any input or visual test. Remotes and server tests still work. Cause unknown; `osascript` to System Events also hung, so ask the user to bring Studio forward.
- A spawn point is picked at random on each Play, so read the character's position before any test that depends on range or facing. `_G` is shared between `execute_luau` calls on the same DataModel, which lets a listener set up in one call be read in a later one.
- Rendering came back on 2026-11-07 in Ticket 7 with no change on our side, though at only 15 fps with Studio in the background. `user_keyboard_input`, `user_mouse_input` and `screen_capture` all worked. Mouse-look still can't be driven, so to aim, read the camera's look and right vectors and hop the character until the target is under the Crosshair.
- Things the camera sees while testing can be test setup, not bugs: a real Shift with no movement Dashes backwards, so near a corner the camera ends up against the wall with the translucent head filling the view, and at (0, -30) the StrafingDummy walks through the camera.
- Multi-client (found in Ticket 8): the user starts it from the toolbar's Play dropdown, **Server & Clients**, with the client count set, as 0 opens a server alone. The server and each client get their own studio id in `list_roblox_studios`, with a null name, so tell them apart with `Players.LocalPlayer`. Test players have negative UserIds. Tool calls run one after another, so overlapping actions need `task.spawn` in an earlier call. Edits still go through the original Edit window while a session runs, but only reach the next session.
- `settings().Network.IncomingReplicationLag` on a client delays its remote events by the full amount (30 → 227 ms) but other players' movement by only about 30 ms, so it understates what a laggy player sees of targets.
- Calls are slow enough to outlast a 6 s Wet, so put Q and E in the same `user_keyboard_input` call.
- `Player.CharacterRemoving` doesn't fire when a character is destroyed outright, but fires late after `LoadCharacter`, so don't use it to track respawns. Time respawns when testing them, as a stray timer can look like recovery.
- Don't call `screen_capture` while a mouse button is held. On 2026-11-07 (Ticket 9) one hung for 120 s, and the queued mouseButtonUp waited behind it, so the held Basic Attack kept swinging and killed a dummy 17 times. Release first, or check the folder of cosmetic parts instead of capturing a 0.12 s effect.
- Server frames get long while Studio is in the background (seen 2026-11-08, Ticket 10), so a live projectile can take steps of several studs, and the same test can give different results between runs. For exact projectile tests, drive a copy of `Projectiles` with a fake `heartbeat` dep, as `ProjectilesSpec` does.
- Before a test that needs a projectile to hit, read the camera's pitch and where the crosshair's aim point lands. On 2026-11-08 (Ticket 12) the camera had been pitched 36° down, by something other than Claude, so a Tidal Bolt went into the floor. Sectors ignore pitch, so they still hit.
- Real input works through `user_keyboard_input` while rendering. Stopping Play prints the session summary, whose `chargeBands` and `chargeEnds` confirm what the server decided.
- In a Play session, a copy of a module made with modified `Source` can stand in for the real one by name, to check that specs fail without a fix. Rename the real one first, and restore it after.
- A test hop that lands inside a solid part makes physics eject the character, and the client can briefly read a wild position (y = -1000000). Set y from a floor raycast.
- At 15 fps, `keyPress` (and keyDown then keyUp in one call) can last longer than the 0.12 s Tap Window, so it counts as a ~1% Charge (Tidal Bolt 12.035). Taps were exact about half the time in Ticket 13, so allow for 12.035 when expecting 12.
- To force a server-rejected Dash from real input (Ticket 13), use up the server's 2 Dash charges with forged `DashRequest`s from that client, then press real LeftShift within the 4 s recharge. The client still thinks it has a charge, so it Dashes and the server answers `NoCharge`.
- Forged Charging tests with large attempt ids raise the server's last-seen id, so the real client's later `ChargeStart`s are refused as `StaleAttempt` until Play restarts. Do them last.
- `execute_luau` shows only the first return value (`return a, b` gives `a`), so return one formatted string. The server id answers only to the "Server" datamodel, and a client id only to "Client". The wrong one gives "Target is not reachable".
- Health regenerates and calls take tens of seconds, so a health read after a shot can already show full health. Set up a `HealthChanged` or `CombatResult` listener before the shot (Ticket 14).
- With the camera yaw fixed, the Aim Point sits about 2.37 studs right of the root's line, so place targets on the camera's aim line. The camera faces the arena centre again on respawn, so re-read its look vector after any death.
- Pressed against cover, the camera's shoulder offset is clipped too, so the Aim Point lands on the cover face within 3 studs and the body-origin fallback applies. To test the hand origin's cover pull-back, forge `ChargeStart{attemptId, abilityId}` then `ChargeRelease{attemptId, abilityId, aimPoint}` with an Aim Point beyond the cover. Use a high id and do it last, as the quirk above warns.
- `AnimationTrack.Stopped` fires after the fade-out ends, so durations measured from it overstate the track. Sample `IsPlaying` and `TimePosition` each frame. A non-looping track that ends by itself fades for about 0.27 s, whatever `fadeSeconds` its `Play` used.
- A test hop run in `task.spawn` from `execute_luau` stalled after about 31 studs. Synchronous hops of up to about 6 steps (3 s) worked every time.
- A 2-client run can stall without an error, and the developer may close the session mid-run. Brief testers to check rendering before each group of checks, keep each call under about 5 s, and run the most important checks first.
- Animations are uploaded by the developer, not through the MCP. Open Cloud accepts animations only as `.rbxm`/`.rbxmx` saved from Studio, and the MCP can't save one. The Animation Editor's Publish only lists animations under a rig's `AnimSaves`, so use right-click **Save to Roblox** on the KeyframeSequence in Explorer instead.
- Setting `workspace.CurrentCamera.CFrame` from `execute_luau` doesn't hold, because the game's camera script overwrites it every frame. To pin pitch and yaw for a projectile test (Ticket 15), bind `RunService:BindToRenderStep("TEMPORARYCamFix", Enum.RenderPriority.Last.Value, …)` on the client to set the camera after it. The binding ends with Play. The camera's yaw and pitch also drifted mid-session with no known cause, so re-check them before each shot.
- (Corrected in Ticket 21: 25 and 40 are the push's speeds in studs per second, not distances. Measured displacement is about 5.4 studs on a tap and 8.7 on a full Charge.) A Tidal Bolt pushes its target 25 studs on a tap and 40 on a full Charge, so a Q then E Reaction test from too far away pushes the target out of Arc Burst's 28-stud range (Ticket 15). Start the target about 12–20 studs away on the aim line, and send Q and E in one call. A server-side `PivotTo` of a player is reverted by Movement Validation, so move characters from their own client.
- `script_read` needs both `start_line_one_indexed` and `end_line_one_indexed_inclusive` for a partial read (Ticket 16). `script_grep` takes plain strings, so a Luau pattern like `%.` finds nothing.
- In Edit mode, `require` from `execute_luau` can return a stale cached copy of a module edited since (Ticket 16: `Tuning.kit` was nil, and new `KitRules`/`PickupRules` functions were missing). So `RunAll` called from Edit shows false failures. Run `RunAll` on the Server in Play, or require a `:Clone()` of the module to read its current values.
- The ShootingDummy near (-33, 11.9, -33) fires at players within about 45 studs, which muddles hit, health and Reaction tests. Use the north-east open area around (-5, 36) to (8, 25).
- To find a projectile's line in a 2-client test, read the `CastStarted` origin and `aimPoint` on the other client. `CastStarted` only goes to other players, so a solo test sees it on neither side. Watch the client's cosmetic-effects folder or sample `ChargingAbility` on the server instead.
- A floor raycast near the low area can hit `FloorLow` at y = -8 rather than the main floor, so check the hit part's name and y before a hop.
- A test hop that passes within 4 studs of a Pickup collects it, since the server's loop sees the character on the way (Ticket 16). Route hops around Pickups, or place the character with a single CFrame set.
- The developer's own Studio input during a tester's run (seen in Ticket 16) can stop Play and add stray Casts. Ask them to leave Studio alone while a tester runs.
- To land two clients in the same server tick (Ticket 16), run `task.delay(T - workspace:GetServerTimeNow(), …)` on each client with the same absolute T about 20 s ahead. The landings differed by under 6 ms. Helpers stored in `_G` keep the old `Character` after `LoadCharacter`, so define them again after any respawn. A server-side `LoadCharacter` is a quick way to reset a Kit to the Starting Kit.
- `user_mouse_input` `moveTo` with an `instance_path` clicks a GUI button even while the mouse is locked to the centre (Ticket 17), so a passing click doesn't prove a real player could reach the button. With the mouse locked, ask whether the cursor can get there at all. `AbsolutePosition` and the capture's pixels differ, so use `instance_path` rather than coordinates.
- Match phases outrun tool calls (Ticket 17): Hub windows of about 15 s, Results of 10 s, and client `execute_luau` round trips of 10 s or more with several clients. Arm a `task.spawn` sampler in `_G` on each client, logging a text snapshot of the UI, `CameraType` and `CameraSubject` every 100 ms on change. Arm timed server actions to wait for `MatchPhase` themselves. Waits of up to about 25 s inside one server call have held. `MatchPhaseEndsAt` is nil while Waiting, so guard any subtraction.
- With a temporary short `maxSeconds`, slow setup can end the Match by Timeout before the next check (Ticket 17). Chain calls quickly, or allow for a new Match about 25 s later.
- To simulate a fall out of the world (Ticket 17), set `CanCollide = false` locally on the floor parts under the character (find them with a `RespectCanCollide` raycast), then restore them. A client teleport to the void is reverted by Movement Validation. The fall reports `Died`, because the Humanoid dies before the character is destroyed.
- `Kick` from the server removes that client's studio id from `list_roblox_studios`, so do leave tests last in a multi-client run.
- The console can keep lines from earlier Play sessions, so read only what follows the latest `[Riftfall] Server started`.
- Standing in a Sentry's sight between tool calls is lethal (Ticket 18): calls take 10–40 s, and a Sentry lands 12 every ~3.2 s, faster than Natural Recovery. Arm everything first, then approach, act and leave within one client call, and top health up with the TEMPORARY hook only between observed shots.
- A Sentry's tap Tidal Bolt pushes its target 20–25 studs, often out of its 45-stud range (Ticket 18). For a second shot, or a follow-up in range of another player, hop back in, and loop on a distance check before melee or Arc Burst.
- A forged `CastRequest` for Tidal Bolt or Arc Burst is rejected as `NotInstant` (Ticket 18). Forge a tap as `ChargeStart` and then `ChargeRelease` with the same attemptId, about 0.03 s apart.
- The arena cover test spot (−2, −14), south of `CoverCentre`, is inside the ShootingDummy's range, and its pushes move the character about 10 studs (Ticket 18). Hop there and fire within about 1.1 s, checking the client's position at fire time.
- A forged Cast draws nothing on the caster's own client, since only real input spawns local visuals. To see a Cosmetic Projectile's impact, watch `CosmeticEffects` on another client, which rebuilds it from `CastStarted` (Ticket 18).
- In solo Play, rendering stayed off for a whole session (0 RenderStepped) even with Play focused. A Server & Clients session started by the developer then rendered both clients at 15 fps (Ticket 18). Keep rendering-dependent checks, such as orb growth or camera collision, for such a session.
- In a Server & Clients session, `get_console_output` on the server's id returned only the first lines of the log (Ticket 18). Read Session lines through `game:GetService("LogService"):GetLogHistory()` on the Server instead.
- With the map at (0, 0, −450), walking from a pad to the centre is 60–110 studs, about 9–15 hops of 7.5 studs every 0.5 s, so split it over several calls. A helper in `_G` that hops toward a target for up to 6 steps per call worked every time, with y set from a floor raycast against `Workspace.MatchMap` only.
- A Knockback timed only by frames lands a frame late or early, and a long server frame cuts a dummy's push short (Ticket 19): a Rift Hook pull first ended 0.8–2 studs past its 4-stud destination on the client, and 1 stud short on a dummy. Pulls now stop on arrival on both. When measuring forced movement, sample every Heartbeat and expect normal pushes to vary by about a frame.
- A Tidal Bolt tap moves its target about 5 studs (25 studs/s for 0.2 s). The 20–25 studs seen from Sentry shots in Ticket 18 included the target's own movement and falls, so don't treat 5 as a short push.
- To test a pull on the player solo (Ticket 19), have a dummy Cast it through a temporary `Casts.castFromServer` helper: the pull goes toward the caster's **current** root, so the fixed StaticDummy at (4, 3.2, 14) is the caster, and the player moves to a spot on a clear line from it.
- A test helper that swaps a Kit slot through `Kits.replace` refuses the Ability already in that slot, so to change its Rank, swap something else in first (Ticket 19). A Pickup dropped by a replacement within 4 studs is collected the moment the Kit fits it again, which can Upgrade a test Kit unexpectedly.
- To line a forged Dash's Evade up with a server-cast hit (Ticket 19), have the server action wait for an absolute server time T, and the client fire the Dash at `T - 0.05` from `workspace:GetServerTimeNow()`. It worked first time.
- **Collapse testing rules (specified in Ticket 22, not yet verified in Studio).** The Collapse consumes the authored Rift Crown by reparenting its Sections into a holding folder, so any test that consumes Sections runs in **Play**, never in persistent Edit mode, and an Edit-mode helper that can trigger a removal must refuse or restore in a `finally`. Play changes should not persist, but after a Play run that consumed Sections, stop Play and rerun the active-map integrity check in Edit before saving or committing a `.rbxl` snapshot. Arm boundary cases against an absolute server timestamp, not tool latency.
- `script_read` can fail with "Script not found" during Play (Ticket 20). Read a script's `Source` through `execute_luau` on the Server instead.
- For an exact Evade test, `Casts.castFromServer` with `BasicAttack` from a root a few studs from the player, aimed at them, is a server-timed Sector hit with no travel time (Ticket 20). A forged `DashRequest` doesn't move the client, but it does start the server's Evade window and use a charge.
- Sounds played from `execute_luau` on a Play client, whether parented to SoundService or played with `Play()`, reported `IsPlaying = true`, but the developer heard nothing (Ticket 20). Sounds played by the game's own `Feedback` were audible in the same session. To let the developer audition sounds, wire them into the game temporarily, for example by cycling the cue on each event and labelling it on screen, and remove that afterwards.
- A `CombatResult` for a hit that did no damage, such as an Evaded one, has no `damage` field (Ticket 20). To bring a player down in one call, loop forged Basic Attacks every 0.45 s from the attacker's client with a distance guard: 17 hits took about 7.5 s.
- In a 3-client run (Ticket 20), `task.spawn` and `task.delay` threads from `execute_luau` often did their first action and never resumed: a `task.wait` after the action didn't return, and Heartbeat samplers logged nothing. A later `task.spawn` sampler did run for 120 s, so it's inconsistent. Prefer a single-shot `task.delay` for an action at an absolute server time, and a synchronous Heartbeat loop in the next call, started at least 4 s early. `loadstring` isn't available.
- `screen_capture` snapshots at the start of its call, so it can't catch Rift Hook's ~0.14 s projectile or ~0.26 s pull beam (Ticket 20). Log the cosmetic objects with a `DescendantAdded`/`DescendantRemoving` watcher on the viewer's client, and leave how they look to the developer. A capture hang of ~120 s once let a Match time out.
- On `MatchMap`, client cameras faced +z at spawn and respawn, not the centre (Ticket 20). A straight hop across the map crosses the core, where a floor raycast lands on top of it, so route around the core with a waypoint.
- Rift Hook's projectile hits the first character on its line (Ticket 20), so a bystander within about 2 studs of the line is hooked instead of the target. A pull goes toward the caster's current position, so a Sentry pushing the caster moves the endpoint.
- To measure a guarded flood (Ticket 20), send 50 `ReplaceRequest`s, each for a distinct valid Pickup. The number of Replace Session lines is the number that reached validation. Throttled warnings give only the first reason and a held-back total, and their counters carry over between Matches.
- A server-side `Humanoid.Health = 0` is a quick elimination for tests (Ticket 20). The body goes within seconds, so place anything needed beside it beforehand. Results lasts about 10 s, then Countdown clears Caches and Pickups, so Cache tests only work during Running or Results.
- Connections such as Heartbeat stored in `_G` kept running reliably across calls in 3-client runs, where `task.spawn` threads didn't (Ticket 20). Build long-running test behaviour as a connection-driven state machine.
- A Studio debugger entry such as `DebuggerManager.TEMPORARY…Debugger` can mirror a temporary script, so check it's gone after deleting the script.
- A 3-client Server & Clients session showed "disconnected" in Studio and stopped answering, after a long security run (Ticket 20). Every id then reported "studio_id is not connected". The developer closed it and started a new one, and the clients came back with new ids. Brief testers to record results as they go, so a dropped session still yields data.
- A `Humanoid:MoveTo` walker can crawl at 0.5–2 studs/s after a Sentry hit, with `MoveDirection` 0 and `WalkSpeed` 16 (Ticket 20). Driving `Humanoid:Move` toward the waypoint each Heartbeat keeps real speed. On `MatchMap` the core blocks a pad's straight line to a central Cache, so approach each central Cache through a waypoint about 52 studs out along its own angle. Expect a spawn-placement jump in the first frame of Running in any per-frame speed check.

- **Ticket 21 measurement methods.** Rendering can die mid-session even after a good start (2 real jumps worked, then `RenderStepped` read 0 and keyboard calls returned Success with no effect). Heartbeat stays at 60 Hz, so a Heartbeat-driven state machine in `_G` can drive the client's real `ForcedMovement` and `Humanoid:Move`/`Jump`, with a position-triggered Dash, and gives jump distance to about ±0.27 studs. `Humanoid:Move` reaches 16 studs/s only after about 1 s, so allow a 1.5 s run-up. Over a void, hold a fixed y when the floor raycast misses, as reusing the current y falls about 24 studs per hop.
- A Dash is level and gravity still acts, so it drops about 6 studs in 0.25 s. A Dash gap is crossable only from the last 8 or so studs before the edge.
- A temporary server helper that calls `Movement.allowDisplacement(player, 700)` every 0.4 s lets one client `root.CFrame` set cross the map. Switch it off before measuring. Setting a Character attribute from the server and watching it with `GetAttributeChangedSignal` on the client makes a timed jump possible inside one server call. `Characters.registerTarget` makes an anchored fake caster, usable as the attacker id for `Casts.castFromServer`, with no body or Kit. `castFromServer` can't charge, so a charged Cast replicates `Casts.deliver` with `ChargeRules.scaleStats`. A server-side `Humanoid.Health` before and after is exact for Sector hits. The projectile's hand origin is root + 0.7 (about y 3.9). Tool calls sent in one block run in order.
- A fall into the void with no Match running respawns the player in the old Arena after about 3 s (no `voidKillY` action outside a Match).
- **Fixture specs for the Collapse (Ticket 22).** `CollapseSpec` builds a throwaway map in `workspace` at y 5000 (a folder named `TEMPORARY...`), runs a `Collapse` instance on it and destroys it in every case, so a failure can't leave the authored Rift Crown consumed. A floor raycast against a fixture must set `RespectCanCollide = true`, as the game's own queries do, or a non-colliding marker such as a Dash shortcut is hit. A spec that only needs state passes its own holding folder and state holder in `ServerStorage`, so it never touches the real Workspace attributes.

- **A temporary config swap in `Tuning` (Ticket 22 step 3).** Changing values for a live smoke through `Source.gsub` or `find` and reverting them the same way is fast, but the revert dropped a trailing comma (`startingKit = "Empty", -- TEMPORARY` back to `startingKit = "Reference"`), and `RunAll` then failed with "Requested module experienced an error while loading" and `Tuning:124: Expected ',' after table constructor element` in the console. Revert with the exact original text, comma included, and check afterwards that `require(Tuning:Clone())` loads and prints the committed values. Marking each swap `TEMPORARY` lets a grep prove the revert.
- **The accelerated schedule works on the real map (Ticket 22 step 3).** `startingKit = "Empty"`, `crownOpenSeconds = 0`, `maxSeconds = 300` and rows at 45, 80, 115 and 150 s with `warnSeconds` 15 and `firstWarnGuardSeconds` 0 validate and run a whole Match in Studio solo (minimum players is 1 there). A server `execute_luau` that polls the Workspace attributes every 0.25 to 0.5 s for up to 24 s catches each state change, and `LogService:GetLogHistory()` holds the `[Riftfall][Collapse]` lines. A player who spawns on a Layer 1 Shard falls at the first removal, which ends the Match and tests the settle window, Results, the reset and a second start in about two minutes.
- **A clone of a server module can be driven in Play on the real map.** `require(ServerScriptService.Server.Pickups:Clone())` with `start({ manual = true, folder = <a TEMPORARY folder>, kits = {}, charging = {}, session = {}, announce = ... })` gives a second instance whose `spawn` and `sweepUnsupported` use the real raycasts against the live map, without touching the game's own Pickups. Destroy the folder and clear `_G` afterwards.

- **`Model:GetBoundingBox` follows the model's pivot, not the world (Ticket 22 step 5).** On the real Rift Crown the Dais box reads (29, 28, 28) with its 29 along its X axis, because its parts are rotated cylinders. Any code that treats the box's local Y as up, or its X and Z as the footprint, is wrong there, and a fixture of unrotated slabs won't show it. Take the 8 corners into the world and box them again, and give a spec a Section stood on its side.
- **A live check on the real map found two bugs the fixture could not (Ticket 22 step 5).** A second `Collapse` instance in Play (`Collapse:Clone()` required, its own `TEMPORARY` holding and state folders, `root = workspace.MatchMap`) with a short schedule, driven from a Heartbeat connection in `_G` so tool latency can't stall it, then `relocate` from sampled floor points after each removal. Rows must pass the settle rule: with `settleSeconds` 1.5 the smallest stable gap must be at least 6 s, so 12, 30, 48 and 66 s with a 10 s Warning works and 12, 24 and 36 does not. Always `restore` and `assertIntact`, destroy the folders and disconnect after.
- **Starting `Collapse:start` before GO needs `ctx.now`.** Without it the instance reads its own clock, which in a spec is `os.clock()` and has nothing to do with the spec's absolute GO, so a spec that expects attributes at `start` passes `now = GO`.
- **The Studio id can change under a session** (seen 2026-11-11 between Ticket 22 steps 3 and 5): `script_read` answered "studio_id is not connected" mid-ticket. Call `list_roblox_studios` again, then check that the earlier edits are still there (grep for a function added last session) before building on them.

- **`multi_edit` with `replace_all` can report success and change nothing (Ticket 22 step 6).** A rename of `expect.near(` in a spec said "2 edits applied" and left every use in place, so the new specs failed with "attempt to call a nil value". Count after any `replace_all`, or do a renaming in Edit mode with `string.gsub` on `Source` and report the count (12 replaced, 0 left).
- **During Play, `script_grep` can miss scripts that only the server has.** It found nothing for text that was in `ServerStorage.Tests` while it found the client's copy of a client script. Read a server script's `Source` through `execute_luau` on the Server instead.
- **A client Heartbeat sampler in `_G` is the way to see a HUD (Ticket 22 step 6).** One call arms it (status text, alert text and arrow, the effects folder, the Workspace attributes, with the seconds digits masked so a countdown tick doesn't log), later calls read `_G.LOG`. It saw the Collapse attributes arrive a few frames apart at a removal, which a one-off read could not. Try the sampler's own code on one frame before leaving it running: a bug in it (a `.Text` read on a Frame returns a child) raised an error every frame and flooded `get_console_output` with thousands of lines.
- **The real client modules can be driven without a Match (Ticket 22 step 6).** In a Reference-Kit Play session, setting the Workspace attributes and a model's `CollapseState` and `CollapseRemovesAt` from `execute_luau` on the Client runs the real `MatchHud` and `CollapseTelegraph` on them, and clearing the attributes proves their cleanup. Nothing replicates, so it needs no revert. Moving the character to a far Section needs the temporary `Movement.allowDisplacement` server helper, called every 0.3 s from a Server Heartbeat connection in `_G`. A client `CFrame` set without it was reverted after about 0.5 s.
- **Replicated attributes written together do not land together (Ticket 22 step 6).** At a Collapse removal the client saw `CollapseLayer` of the next layer with the last layer's `CollapseWarning` and `CollapseRemovesAt` for several frames. Any client presentation that combines attributes needs to hold for a short settle (80 ms here) rather than trust one frame's read.
- `screen_capture` needs a `capture_id` such as `ScreenCapture_1`. It does show a `Highlight`, a Neon beacon and the HUD in Play.

- **An Edit-mode structural pass does not prove a Match will start its Collapse (Ticket 22 step 9a).** A Match sets up its Caches and Sentries before `Collapse:prepare` runs, so a check that sees them behaves differently from one run on the bare map in Edit. The Dais isolation check counted their bodies as ground, and every Match started with `plays without a Rift Collapse`. ## Touch and device testing (Ticket 29, found while specifying it, 2026-11-12)

[Ticket 29](../milestone-2-tickets.md#29-platform-input-and-mobiletablet-support) is specified and not built. These are facts about the tooling, found while specifying it. The Roblox API and device questions it still has are listed under **Implementation checks** in the ticket, not here.

- **The MCP has no touch input.** `user_keyboard_input` and `user_mouse_input` are the only input tools, so touch behaviour can't be driven or checked by `studio-tester`. Use the Studio Device Simulator by hand and real devices, and keep keyboard and mouse regression checks in Play.
- **`inspect_instance` returned no properties for `StarterPlayer` or `Workspace`.** Touch settings such as `DevTouchMovementMode` and `AutoJumpEnabled`, and `Workspace.SignalBehavior`, have to be read in Studio's Properties panel.
- **Roblox's player scripts (`PlayerModule`) were found only while Studio was in Play.** In Edit mode no `PlayerModule` was found under `StarterPlayer`, and a `script_read` of `StarterPlayer.PlayerModule.ControlModule` worked once Studio was in Play. That sits oddly with the quirk above that `script_read` can't read a script in Play, so treat it as unconfirmed for other scripts. Reading needs no change to the session, but starting Play does, so ask first.
