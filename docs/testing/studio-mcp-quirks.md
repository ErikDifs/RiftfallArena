# Studio MCP testing quirks

What the `Roblox_Studio` MCP can and can't verify in Riftfall Arena playtests, and the traps that have given false results. Found from Ticket 1 onwards. Read this before any Studio test run. It is the project's canonical testing reference, so add new quirks here.

Code is edited through the MCP rather than Rojo, as [ADR-0005](../adr/0005-game-code-lives-in-studio-edited-through-mcp.md) sets out.

- `multi_edit` reads a dot in a script path as a separator, so `Foo.spec` makes a folder. Avoid dots in instance names.
- `user_mouse_input` moves don't produce look input while the mouse is locked, so only the user can test mouse-look. Button down and up do work, but every call needs an x/y or `moveTo`, or a mouseButtonUp fails and leaves the button held.
- `screen_capture` does not show `AlwaysOnTop` BillboardGuis. It's unknown whether they render normally, so Hud elements are used where they must be verified.
- `AbsolutePosition` inside a BillboardGui is relative to the billboard, so it says nothing about where it is on screen.
- After teleporting a character from the client, wait over 1 s before a server-side check: the server sees the new position late, and a 0.3 s wait produced a false range failure.
- Scripts can't be edited during Play. Stop Play first.
- The studio id changes when Studio reopens, so call `list_roblox_studios` again.
- `game.PlaceVersion` may not refresh after a publish, so it doesn't prove a publish hasn't happened.
- `require` inside `execute_luau` gives a fresh module instance, not the running game's. It can't reach live state such as `Movement`, though it's useful for testing a module with fakes. Instances, attributes and tags are shared. To change config for a live test, edit it in Edit mode and revert it after.
- Since Ticket 4, Movement Validation corrects test teleports. Move the character in hops of about 8 studs every 0.5 s. `character_navigation` reported success once without moving it.
- The user can be in the same Studio session during tests. Unexplained Casts or a stopped Play may be them, so ask before calling it a bug.
- `settings().Network` persists across Studio restarts: record the starting values and restore them after a latency test.
- A built-in `rbxasset://` sound can fail to load (`swoosh.wav` does). Check `IsLoaded` before relying on one.
- To reach live server modules, add a temporary Script under `Server` that requires them and exposes a BindableFunction in ServerStorage, then call it from `execute_luau`. Name it TEMPORARY, delete it after and grep for the word. It can fire real projectiles at the player, since no dummy shoots.
- `screen_capture` works during Play and shows the player's real view, Hud included, but ignores its camera arguments, so stand where you need the view.
- The viewport can stop rendering mid-session (seen 2026-11-07, Ticket 6), and restarting Play doesn't fix it. Then `RenderStepped` never fires (Heartbeat still does), tweens freeze, `user_keyboard_input` reports success without reaching `UserInputService`, and `user_mouse_input` and `screen_capture` hang past 120 s. Check by counting `RenderStepped` for a second before trusting any input or visual test. Remotes and server tests still work. Cause unknown; `osascript` to System Events also hung, so ask the user to bring Studio forward.
- A spawn point is picked at random on each Play, so read the character's position before any test that depends on range or facing. `_G` is shared between `execute_luau` calls on the same DataModel, which lets a listener set up in one call be read in a later one.
- Rendering came back on 2026-11-07 in Ticket 7 with no change on our side, though at only 15 fps with Studio in the background. `user_keyboard_input`, `user_mouse_input` and `screen_capture` all worked. Mouse-look still can't be driven, so to aim, read the camera's look and right vectors and hop the character until the target is under the Crosshair.
- Things the camera sees while testing can be test setup, not bugs: a real Shift with no movement Dashes backwards, so near a corner the camera ends up against the wall with the translucent head filling the view, and at (0, -30) the StrafingDummy walks through the camera.
- Multi-client (found in Ticket 8): the user starts it from the toolbar's Play dropdown, **Server & Clients**, with the client count set, as 0 opens a server alone. The server and each client get their own studio id in `list_roblox_studios`, with a null name, so tell them apart with `Players.LocalPlayer`. Test players have negative UserIds. Tool calls run one after another, so overlapping actions need `task.spawn` in an earlier call. Edits still go through the original Edit window while a session runs, but only reach the next session.
- `settings().Network.IncomingReplicationLag` on a client delays its remote events by the full amount (30 → 227 ms) but other players' movement by only about 30 ms, so it understates what a laggy player sees of targets.
- Calls are slow enough to outlast a 6 s Wet, so put Q and E in the same `user_keyboard_input` call.
- `Player.CharacterRemoving` doesn't fire when a character is destroyed outright, but fires late after `LoadCharacter`, so don't use it to track respawns. Time respawns when testing them, as a stray timer can look like recovery.
- Don't call `screen_capture` while a mouse button is held. On 2026-11-07 (Ticket 9) one hung for 120 s, and the queued mouseButtonUp waited behind it, so the held Basic Attack kept swinging and killed a dummy 17 times. Release first, or check the folder of cosmetic parts instead of capturing a 0.12 s effect.
- Server frames get long while Studio is in the background (seen 2026-11-08, Ticket 10), so a live projectile can take steps of several studs, and the same test can give different results between runs. For exact projectile tests, drive a copy of `Projectiles` with a fake `heartbeat` dep, as `ProjectilesSpec` does.
- Before a test that needs a projectile to hit, read the camera's pitch and where the crosshair's aim point lands. On 2026-11-08 (Ticket 12) the camera had been pitched 36° down, by something other than Claude, so a Tidal Bolt went into the floor. Sectors ignore pitch, so they still hit.
- Real input works through `user_keyboard_input` while rendering. Stopping Play prints the session summary, whose `chargeBands` and `chargeEnds` confirm what the server decided.
- In a Play session, a copy of a module made with modified `Source` can stand in for the real one by name, to check that specs fail without a fix. Rename the real one first, and restore it after.
- A test hop that lands inside a solid part makes physics eject the character, and the client can briefly read a wild position (y = -1000000). Set y from a floor raycast.
- At 15 fps, `keyPress` (and keyDown then keyUp in one call) can last longer than the 0.12 s Tap Window, so it counts as a ~1% Charge (Tidal Bolt 12.035). Taps were exact about half the time in Ticket 13, so allow for 12.035 when expecting 12.
- To force a server-rejected Dash from real input (Ticket 13), use up the server's 2 Dash charges with forged `DashRequest`s from that client, then press real LeftShift within the 4 s recharge. The client still thinks it has a charge, so it Dashes and the server answers `NoCharge`.
- Forged Charging tests with large attempt ids raise the server's last-seen id, so the real client's later `ChargeStart`s are refused as `StaleAttempt` until Play restarts. Do them last.
- `execute_luau` shows only the first return value (`return a, b` gives `a`), so return one formatted string. The server id answers only to the "Server" datamodel, and a client id only to "Client". The wrong one gives "Target is not reachable".
- Health regenerates and calls take tens of seconds, so a health read after a shot can already show full health. Set up a `HealthChanged` or `CombatResult` listener before the shot (Ticket 14).
- With the camera yaw fixed, the Aim Point sits about 2.37 studs right of the root's line, so place targets on the camera's aim line. The camera faces the arena centre again on respawn, so re-read its look vector after any death.
- Pressed against cover, the camera's shoulder offset is clipped too, so the Aim Point lands on the cover face within 3 studs and the body-origin fallback applies. To test the hand origin's cover pull-back, forge `ChargeStart{attemptId, abilityId}` then `ChargeRelease{attemptId, abilityId, aimPoint}` with an Aim Point beyond the cover. Use a high id and do it last, as the quirk above warns.
- `AnimationTrack.Stopped` fires after the fade-out ends, so durations measured from it overstate the track. Sample `IsPlaying` and `TimePosition` each frame. A non-looping track that ends by itself fades for about 0.27 s, whatever `fadeSeconds` its `Play` used.
- A test hop run in `task.spawn` from `execute_luau` stalled after about 31 studs. Synchronous hops of up to about 6 steps (3 s) worked every time.
- A 2-client run can stall without an error, and the developer may close the session mid-run. Brief testers to check rendering before each group of checks, keep each call under about 5 s, and run the most important checks first.
- Animations are uploaded by the developer, not through the MCP. Open Cloud accepts animations only as `.rbxm`/`.rbxmx` saved from Studio, and the MCP can't save one. The Animation Editor's Publish only lists animations under a rig's `AnimSaves`, so use right-click **Save to Roblox** on the KeyframeSequence in Explorer instead.
- Setting `workspace.CurrentCamera.CFrame` from `execute_luau` doesn't hold, because the game's camera script overwrites it every frame. To pin pitch and yaw for a projectile test (Ticket 15), bind `RunService:BindToRenderStep("TEMPORARYCamFix", Enum.RenderPriority.Last.Value, …)` on the client to set the camera after it. The binding ends with Play. The camera's yaw and pitch also drifted mid-session with no known cause, so re-check them before each shot.
- A Tidal Bolt pushes its target 25 studs on a tap and 40 on a full Charge, so a Q then E Reaction test from too far away pushes the target out of Arc Burst's 28-stud range (Ticket 15). Start the target about 12–20 studs away on the aim line, and send Q and E in one call. A server-side `PivotTo` of a player is reverted by Movement Validation, so move characters from their own client.
